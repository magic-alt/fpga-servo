## 目标与范围

将当前分散的脚本整理为可复用的 KiCad PCB 开发、测试和验证工具集。后续板卡通过工程配置和领域规则接入，不再为每项检查建立一个顶层脚本。同步整理 docs，让当前设计说明、使用指南和历史证据各有明确入口。

本轮支持 KiCad 10 与 Python 3.12，以标准库为默认依赖。支持 Windows 和 Linux，工具路径由命令参数或 PATH 提供。原生 KiCad 操作需要 kicad-cli，板级开发辅助按需使用 pcbnew，现有理想电路仿真按需使用 ngspice。其他 EDA 只预留适配边界，不宣称已经支持。

不修改原理图、PCB、符号库、封装、BOM 选型或 FPGA 引脚定义。保留现有未跟踪文件。零 ERC、DRC 或自动检查通过不代表实物、热设计或生产放行。

## 当前问题

- tools 顶层有 43 个 Python 文件；检查、测试、公共解析、历史修复和开发操作混放。
- 多个脚本直接依赖脚本名和相对文件深度，工程目录和元件引用被写在通用执行逻辑里。
- CI 和 Gate A/B 逐一调用脚本，新增功能必须同步维护多份调用列表。
- AD7606C 工程有独立工具，并通过修改导入路径、runpy 等方式复用旧工程检查。
- docs 混合当前规范、采购证据、多轮修复记录与旧计划；发布门禁中的历史完成项可能被误读为当前状态。

## 工具结构

采用一个命令入口和按领域组织的 Python 包，不把所有代码拼成巨型脚本，也不只做脚本转发器。

```text
tools/
  pcb.py                   # 唯一日常命令入口
  pcbtools/
    cli.py                 # 参数、命令与错误呈现
    project.py             # 配置加载、路径与能力校验
    report.py              # 结果、来源和证据序列化
    kicad.py               # 原生执行与公共数据解析
    schematic.py           # 原理图通用检查
    board.py               # PCB、网表一致性与通用板级检查
    export.py              # BOM、网表、图纸导出
    development.py         # 开发辅助、预览与产物保护
    rules/                 # 按领域组织的规则集与工程适配
  projects/                # 两个工程的声明式配置及接入模板
  tests/                   # 迁移后的回归测试
  archive/                 # 明确过时的一次性工具和调用说明
  ai_pcb_guide/            # 外部参考材料，保留来源与边界
```

模块可以依据实际大小划分子包，但不能以一条规则一个文件为默认模式。共享解析、工程配置、结果结构和执行逻辑必须实际复用。现有入口迁移后更新仓库内全部调用，避免永久保留一套旧包装脚本。

## 工程与规则接口

工程配置使用 JSON，包含 schema_version、工程标识、相对配置文件的工程根目录、顶层原理图、可选 PCB、库、BOM、输出位置、启用规则集及规则参数。校验未知字段、缺失文件和冲突配置。项目标识可选择仓库内配置，也可通过配置文件路径接入仓库外工程。

层次页从顶层原理图递归枚举，检测缺失引用、重复和循环；不依赖固定页名或页数。默认输出位于独立证据目录，不能覆盖输入文件。工程路径允许空格；调用外部程序使用参数列表，不使用拼接 shell 命令。

通用检查显式接收工程上下文与解析数据，不从模块所在目录推导被测工程。OCP 物理引脚、ADC 配置、功率器件和 Kelvin 要求归入规则集，只有配置启用后才执行。ADS8588S 与 AD7606C 分别提供配置；已有工程保留所有有效约束，不因通用化降低检查要求。

新项目能仅用通用规则运行。缺少 PCB 的工程可以运行原理图工作流，但请求 PCB 工作流时必须报告缺失前置条件，不能静默通过。不适用规则须有配置依据；请求中必需的规则不允许以不适用绕过。

## 命令与结果约定

统一命令按工程与工作流组织，例如：

```sh
python tools/pcb.py check --project ads8588s --scope schematic
python tools/pcb.py check --project ad7606c --scope schematic
python tools/pcb.py check --config path/to/project.json --scope pcb
python tools/pcb.py verify --project ads8588s --scope release
python tools/pcb.py export --project ads8588s --kind bom
python tools/pcb.py develop --project ads8588s --operation sync --preview
python tools/pcb.py test
```

具体子命令在实施计划中锁定。check 执行规则，verify 编排新鲜原生导出和完整证据流程，export 生成独立产物，develop 包含经过迁移及验证的开发操作。未实现的操作明确报错，不提供空壳成功命令。危险的历史布线工具不自动纳入通用工作流。

单项状态包括 PASS、FAIL、NOT_RUN、NOT_APPLICABLE；发布决策另外记录 BLOCKED。结果包含规则标识、工程、输入摘要、工具版本、命令、输出路径、失败原因和时间。每次证据运行使用独立目录，不复用旧报告作为新结果。

必需检查失败、工具缺失、异常或超时必须导致总体非零退出。配置或用法错误有明确诊断；严格发布门禁阻断保留可区分的退出语义。原生报告记录组件数、网络数、ERC 错误/警告/排除，以及 DRC 和未连接数量。保留原生严重级别，不修改排除或电气连接来获得通过。

## 开发辅助边界

默认只读检查。开发操作默认预览，写入需要显式 apply 参数；修改前备份并报告目标路径、前后摘要及差异。原理图同步使用项目规则允许的原生能力，不通过编造文本制造网表一致。没有可用原生同步接口时报告未执行及操作步骤。

旧的硬编码修复和自动布线脚本先确认调用者和适用设计版本。可复用算法迁入领域模块；仅适用于历史板卡的操作连同说明归档，不作为任意板卡可安全执行的功能。禁止在回归测试或日常验证中执行修改实际板卡的操作。

## 迁移与验收

1. 记录现有检查与测试基线，列出每个旧入口的保留、合并或归档去向。
2. 先建立工程配置、共享模型和失败语义；使用临时工程覆盖未知配置、缺失工具、异常和超时。
3. 按原理图、PCB、导出、验收与开发领域迁移实际逻辑；同步迁移现有回归测试，保留有效故障检测能力。
4. 对两个现有工程及一个不含伺服专属命名的临时第三工程验证通用规则与工程隔离。
5. 更新 CI 和全部实际调用；验证配置路径含空格、仓库外工程、递归层次及输出隔离。
6. 归档文档与历史工具，检查当前文档链接和已迁移入口引用。
7. 运行完整 Python 回归和可用的原生工具检查，比较迁移前后检查集合、发现项及退出结果。

报告分别列出已执行、未执行和当前设计已知失败。没有本机原生工具或 Linux/硬件条件的项目不能记为通过。严格 PCB/release 流程必须继续暴露既有未同步板卡和动态资格阻断。

验收标准：日常入口收敛；公共能力脱离伺服元件和固定路径；两个现有工程规则不减少；第三工程无需复制检查脚本即可接入通用验证；开发功能不会在默认验证中改板；文档和 CI 可追溯且没有陈旧的有效调用。
