# OCP 故障锁存设计（已确认）

## 目标与范围

将现有“故障消失即恢复”的组合 OCP 改成硬件锁存关断。保持 J1 PWM、GATE_EN、FAULT_CLEAR、OCP_N 的既有接口分配；不依赖 FPGA 固件才能关断。用户已于 2026-10-09 确认本规格，实施记录见对应计划与后续审查。

本子任务只实现安全使能锁存及上电复位。母线浪涌/再生功率级与最终 PCB 布线分阶段处理，不能用本子任务完成代替整板工业级验收。

## 方案比较

1. **推荐：异步清零 D 触发器作为 ARM 锁存**。电源/故障条件强制清零；FAULT_CLEAR 上升沿仅在 GATE_EN=0 时重新武装。可以明确验证清除保持、重复故障和上电状态。
2. 交叉耦合 NOR/SR 锁存：器件常见，但同时置位/复位及上电状态须额外约束，不选作本轮默认方案。
3. FPGA 维护软件故障状态：不能替代独立硬件锁存，不采用。

## 电气行为与连接意图

- 新增 SN74LVC1G74（3.3V）作为 ARM 锁存；具体订货后缀及封装按制造商机械图选定。
- D 接反相后的 GATE_EN；CLK 接有明确下拉及边沿整形的 FAULT_CLEAR。
- /PRE 固定接 VIO_3V3，避免与 /CLR 同时有效。
- /CLR 接 HEALTHY_N：只有原始 OCP 正常、12V/5V PWR_GOOD 正常且电源复位监控有效时，/CLR 才为高。任何故障异步清零 ARM。
- Q=ARMED。U11 的第三输入从原始 OCP_N 改接 ARMED，RUN_OK=GATE_EN & PWR_GOOD & ARMED。
- 原始 OCP_N 保留给 FPGA 作实时诊断；锁存状态引出测试点。FAULT_CLEAR 通过现有 J1 pin 10 实际接入硬件。
- 使用电源监控器确定 VIO_3V3 上电/欠压复位，且验证 VA_5V 失电也产生硬件禁止。不得依赖普通 RC 或触发器的未知上电值建立 ARM 初值。
- 每颗新增 IC 有独立 100nF 本地去耦；默认偏置器件必须装配，不作 DNP。

## 状态验收表

| 条件 / 操作 | ARMED | RUN_OK |
|---|---:|---:|
| 上电复位有效 | 0 | 0 |
| 健康但未执行有效 FAULT_CLEAR 边沿 | 0 | 0 |
| 健康、GATE_EN=0，FAULT_CLEAR 上升沿 | 1 | 0 |
| 已武装且健康，GATE_EN=1 | 1 | 1 |
| 任一 OCP 或电源故障 | 0 | 0 |
| 故障消失但无新清除边沿 | 0 | 0 |
| 故障中执行 FAULT_CLEAR | 0 | 0 |
| GATE_EN=1 时执行 FAULT_CLEAR | 0 | 0 |
| FAULT_CLEAR 持续高，故障发生又消失 | 0 | 0 |

GATE_EN 高时的清除脉冲应解除武装而非允许运行；清除操作顺序固定为 GATE_EN 拉低、确认健康、发出清除边沿、再允许 GATE_EN 拉高。

## 验证要求

- 自动网表检查验证 D/CLK、/CLR、/PRE、ARMED 与 U11 的真实引脚连接及默认偏置。
- 行为/时序验证覆盖表内全部场景、清除与故障竞争、短故障脉冲、FAULT_CLEAR 卡高、VIO/VA_5V/VDRV_12V 不同上下电顺序。
- 根据数据手册最坏延迟形成 OCP 到 FD6288 输入的关断时间预算，计入输入 RC、比较器、清零及逻辑延迟；台架用实际 gate-to-source 波形确认。
- 仓库检查、BOM 一致性和 ERC 必须通过；任何违规必须修复或记录真实原因，不降低规则清零。
- 该单通道硬件禁止不是安全认证的 STO，不作 SIL/PL 声明。

## 审阅决定

用户已确认采用“故障锁存；GATE_EN=0 且健康时，FAULT_CLEAR 上升沿重新武装”的策略。按逐器件实施计划执行原理图和回归修改。

## 实施细化

开漏 POR/OCP/PG 经 U26 三通道施密特缓冲，PWR_READY 是 PWR_GOOD 的整形信号；RUN_OK 实际为 GATE_EN & PWR_READY & ARMED。此细化保持原故障优先和低使能边沿重武装行为。最终 158 器件 / 183 网络；时序条件和台架门槛见 `docs/ocp_latch_review_2026-10-09.md`。
